# uaxfmt 仕様

UAX #14(Unicode Line Breaking Algorithm)に基づき、日本語の禁則処理を行う
Windows 用テキスト整形フィルタ。

- 実装言語: Rust(単体 exe、サイズ優先ビルド)
- 言語: プログラムが出すメッセージ(ヘルプ、エラー、`-p` の出力のコメント)とソースコードのコメントは英語。
  仕様書などのドキュメントは日本語。

## 1. 入出力

```
uaxfmt [オプション]
```

| オプション | 意味 | 省略時 |
|---|---|---|
| `-i FILE` | 入力ファイル(`-` は標準入力) | 標準入力 |
| `-o FILE` | 出力ファイル(`-` は標準出力) | 標準出力 |
| `-c FILE` | 設定ファイル(→ 2 章) | exe と同じ場所の設定ファイル |
| `-w N` | `width`(折り返し桁数) | 設定ファイルの値。なければ既定値 `80` |
| `-g N` | `hang`(ぶら下げを許す文字数) | 設定ファイルの値。なければ既定値 `1` |
| `-a N` | `ambiwidth`(曖昧幅の文字の幅。`1` / `2` / `auto`) | 設定ファイルの値。なければ既定値 `auto` |
| `-p` | 最終的に使われる設定を TOML 形式で出力して終了する(→ 2 章「設定ファイルの作成」) | |
| `-h` | ヘルプを表示して終了する | |
| `-v` | バージョンを表示して終了する | |

- オプションは 1 文字の短い名前だけとし、長い名前(`--width` など)は設けない。
- 値は `-w 72` と `-w72` のどちらの書き方でも受け付ける。
- コマンドラインで指定できるパラメータは、よく使うものに絞る。それ以外は設定ファイルで指定する(汎用の `--set KEY=VALUE` のような仕組みは設けない)。
- 将来、真偽値のオプションを追加する場合は `-s false` のように値を渡す形にする。
- 入力と出力が同じファイルの場合はエラー(パスを正規化して比較し、`.\a.txt` と `a.txt` のような書き方の違いも検出する)。

### 文字コード

入力の文字コードを判定し、出力も同じ文字コードで書く。
整形で増えるのは空白と改行だけなので、入力と同じ文字コードに戻しても表せない文字は生じない。

対応する文字コード: UTF-8、UTF-16LE、UTF-16BE、CP932(Shift_JIS)、EUC-JP、ISO-2022-JP

判定の順序(`encoding = "auto"` のとき):

1. BOM がある → UTF-8 / UTF-16LE / UTF-16BE のいずれかに確定
2. ISO-2022-JP のエスケープシーケンス(`ESC $ B` など)がある → ISO-2022-JP
3. UTF-8 として正しく読める → UTF-8(ASCII だけの入力もここに含まれる)
4. それ以外 → バイトの出現傾向から CP932 か EUC-JP かを判定する。判断がつかなければ CP932

- 判定が外れる場合に備え、設定ファイルの `encoding`(→ 3.6)で文字コードを強制指定できる。
- 指定(または判定)した文字コードとして正しく読めない入力はエラー(終了コード 1)とし、
  メッセージで `encoding` の指定を案内する。
- UTF-8 / UTF-16 以外の変換には Windows API(`MultiByteToWideChar` / `WideCharToMultiByte`)を使う。
  変換表を exe に持たないので、サイズは増えない。

### 改行コードと BOM

- 改行コードは入力に合わせる。入力中で最初に現れた改行コード(CRLF / LF)を出力全体に使う。
  入力に改行がない場合は CRLF とする。
- 入力の先頭に BOM があれば受け付け、出力にも同じ BOM を付ける。
- 入力の末尾に改行があるかどうかも出力に引き継ぐ。

### ヘルプ(`-h`)

標準出力に出して終了コード 0 で終わる。80 桁に収める。

```
uaxfmt 0.1.0 - text formatter with UAX #14 line breaking and Japanese kinsoku

Usage: uaxfmt [options]
  Reads text, reformats paragraphs, and writes the result.
  Input and output default to stdin and stdout.

Options:
  -i FILE   input file
  -o FILE   output file
  -c FILE   config file
  -w N      line width; 0 joins lines without wrapping        [72]
  -g N      max chars allowed to hang past the width; 0 = off [1]
  -a N      width of East Asian ambiguous chars: 1, 2 or auto [auto]
  -p        print the effective config as TOML and exit
  -h        print this help and exit
  -v        print version and exit

  Values in [ ] are the current settings.

Config file:
  C:\tools\uaxfmt.toml (loaded)
  Run 'uaxfmt -p' to see all settings.

Examples:
  uaxfmt -i in.txt -o out.txt
  type in.txt | uaxfmt -w 72
  uaxfmt -p -o C:\tools\uaxfmt.toml
```

- `[ ]` 内は既定値ではなく**現在の値**(設定ファイルとコマンドラインを反映した値)を表示する。
- 設定ファイルは実際のパスと状態を表示する。状態は次のいずれか。
  - `(loaded)`: 既定の設定ファイルを読み込んだ
  - `(not found; using defaults)`: 既定の設定ファイルがない
  - `(specified with -c)`: `-c` で指定したファイルを読み込んだ
- 各パラメータの詳細はヘルプに載せず、`-p` の出力のコメントで説明する。

### エラーと終了コード

エラーメッセージは標準エラー出力に、`uaxfmt: ` を前置して出す。
オプションの誤りではヘルプ全体を出さず、次の 2 行だけを出す。

```
uaxfmt: unknown option: -x
Run 'uaxfmt -h' for help.
```

| 終了コード | 意味 |
|---|---|
| 0 | 正常終了 |
| 1 | 実行時のエラー(ファイルが開けない、入出力が同じファイル、設定ファイルの誤りなど) |
| 2 | コマンドラインの誤り(不明なオプション、値の不足・不正など) |

### コンソールへの出力

起動時に標準出力・標準エラー出力がコンソールかどうかを判定する(`GetConsoleMode` が成功すればコンソール)。

| 出力するもの | コンソールの場合 | リダイレクト・パイプ・`-o` の場合 |
|---|---|---|
| 整形結果 | `WriteConsoleW` で文字として書く。BOM は付けない | 入力と同じ文字コード・BOM のバイト列 |
| ヘルプ・エラー・`-p` の出力 | `WriteConsoleW` で文字として書く | UTF-8(BOM なし) |

- `WriteConsoleW` はコンソールのコードページ(日本語版 Windows の既定は CP932)に関係なく正しく表示され、
  CP932 にない文字(𠮷 や絵文字など)もフォントが対応していれば表示される。
  UTF-8 のバイト列をそのまま書くと、CP932 のコンソールでは文字化けするため、この方法をとる。
- パイプの先での表示は受け取る側の解釈に依存する(例: UTF-8 の出力を cmd.exe の `more` や
  PowerShell のコマンドレットに渡すと、CP932 として解釈されて文字化けする)。uaxfmt 側では対処せず、
  README に注意として記載する(PowerShell では `[Console]::OutputEncoding = [Text.Encoding]::UTF8` で解決できる)。

## 2. 設定

### 優先順位(上ほど優先)

1. コマンドラインオプション
2. 設定ファイル
3. 組み込み既定値

### 設定ファイルの場所

- 既定: exe と同じフォルダの `<exeのベース名>.toml`
  - 例: `C:\tools\uaxfmt.exe` → `C:\tools\uaxfmt.toml`
  - exe を別名でコピーすると、別の設定で動かせる(例: `mailfmt.exe` → `mailfmt.toml`)
  - exe の場所は、ショートカットや PATH 経由の起動でも実体のパスから求める
  - ファイルがなければ組み込み既定値で動作する(エラーにしない)
- `-c FILE`: 指定したファイルを既定の設定ファイルの**代わりに**使う(合成しない)
  - 指定したファイルが存在しなければエラー

### 書式

TOML。使う型は文字列・整数・真偽値・文字列の配列のみ。
サイズ削減のため、必要な範囲だけを読む小さなパーサを自作する。書式は TOML 互換に保つ。

- 設定ファイルに書かれていないキーは、組み込み既定値を使う(キーごとに判断する)。
- 読み込める文字コード: UTF-8(BOM あり・なし)、UTF-16LE(BOM 付き)。
  Windows PowerShell 5.1 の `>` で作ったファイル(UTF-16LE)も読めるようにするため。

### 設定ファイルの作成

`-p` は最終的に使われる設定(組み込み既定値 ← 設定ファイル ← コマンドラインの順で上書きした結果)を
TOML 形式で出力する。

- 出力先は `-o` に従う(省略時は標準出力)。`-o` で指定した場合は uaxfmt が直接書くので、
  シェルに関係なく常に UTF-8(BOM なし)になる。
- 全キーを出力し、各キーの意味と既定値をコメントで添える(設定ファイル編集時の説明書を兼ねる)。

```
uaxfmt -p -o C:\tools\uaxfmt.toml        # 既定値で設定ファイルを作る
uaxfmt -p -w 72 -g 2 -o uaxfmt.toml      # width=72, hang=2 にした設定ファイルを作る
```

出力例:

```toml
# uaxfmt config file

# Line width in display columns (full-width chars count as 2).
# 0 joins lines without wrapping. (default: 80)
width = 72

# Max number of chars allowed to hang past the width. 0 disables hanging.
# (default: 1)
hang = 2
```

## 3. パラメータ

### 3.1 幅

| キー | 型 | 既定値 | 意味 |
|---|---|---|---|
| `width` | 整数 | `80` | 折り返し桁数(表示幅。全角文字は 2)。`0` なら折り返さず、段落内の行の結合だけを行う |
| `ambiwidth` | 整数または文字列 | `"auto"` | East Asian Ambiguous 文字(`○※①―“”` など)の幅。`1`、`2`、`"auto"` のいずれか。幅の計算と UAX #14 での判定(AI クラスを AL/ID のどちらとみなすか)の両方に使う |
| `tabstop` | 整数 | `8` | 幅を計算するときのタブ幅 |

`ambiwidth = "auto"` のときは、入力の文字コードで幅を決める。

| 入力の文字コード | 幅 | 理由 |
|---|---|---|
| CP932、EUC-JP、ISO-2022-JP | 2 | これらの文字コードでは曖昧幅の文字はすべて 2 バイト文字で、全角で表示されるのが普通なため |
| UTF-8、UTF-16 | 1 | 最近のエディタやターミナルは曖昧幅の文字を半角で表示することが多いため |

- 曖昧幅の文字かどうかは Unicode の属性(UAX #11)で決まり、文字コードには関係しない。
  文字コードが影響するのは、`auto` のときの幅の選択だけである。
- `ambiwidth` は uaxfmt が折り返し位置を決めるときの数え方であり、ターミナルでの表示幅を変えるものではない。
  整形した文章を見る環境(エディタ、ターミナル、印刷など)に合わせて指定する。

### 3.2 改行位置の判定

| キー | 型 | 既定値 | 意味 |
|---|---|---|---|
| `ascii_break` | 文字列 | `"space"` | 半角文字どうしの間の改行規則。`"space"`: 空白でのみ改行(`well-known` や URL を途中で切らない)。`"uax14"`: ハイフンの後なども UAX #14 に従って改行 |
| `strict` | 真偽値 | `true` | 長音記号・小書き仮名(UAX #14 の CJ クラス)の前での改行を禁止する。`false` なら許可する |
| `no_single_letter_end` | 真偽値 | `false` | 1 文字の単語(英語の `a`、`I` など)の直後では、できるだけ改行しない(Vim の `fo=1` 相当) |

全角文字を含む位置の改行判定は、常に UAX #14 の規則表に従う。

### 3.3 禁則処理

| キー | 型 | 既定値 | 意味 |
|---|---|---|---|
| `hang` | 整数 | `1` | ぶら下げを許す最大**文字数**(`0` でぶら下げなし) |
| `no_line_start` | 文字列 | 下記 | 行頭禁則文字(ぶら下げ対象) |
| `no_line_end` | 文字列 | 下記 | 行末禁則文字(追い出し対象) |

文字一覧のキーには `_add`(既定値に追加)/ `_remove`(既定値から削除)版も用意する。
例: `no_line_start_add = "…"`

既定の `no_line_start`:

| 分類 | 文字 |
|---|---|
| 句読点 | `、。，．,.` |
| 閉じ括弧・閉じ引用符 | `）〕］｝〉》」』】〙〗〟’”｠⦆»)]}` |
| 繰り返し記号・長音 | `ヽヾゝゞ々ー` |
| 小書き仮名 | `ァィゥェォッャュョヮヵヶぁぃぅぇぉっゃゅょゎゕゖ` |
| ハイフン・波ダッシュ類 | `‐゠–〜～` |
| 区切り約物 | `？！‼⁇⁈⁉?!・：；:;` |
| その他 | `…°′″` |

既定の `no_line_end`:

| 分類 | 文字 |
|---|---|
| 開き括弧・開き引用符 | `（〔［｛〈《「『【〘〖〝‘“｟«([{` |

### 3.4 行の結合

| キー | 型 | 既定値 | 意味 |
|---|---|---|---|
| `join_space` | 文字列 | `"M"` | 段落内の行を結合するとき空白を入れるか。`"M"`: どちらかが全角文字なら入れない。`"B"`: 両方が全角文字なら入れない。`"always"`: 常に入れる |
| `sentence_space` | 真偽値 | `false` | 結合するとき、`.?!` の後に空白を 2 つ入れる |
| `trim_trailing` | 真偽値 | `true` | 出力するすべての行の行末の空白を削除する(折り返し位置の空白は、この設定にかかわらず常に削除する) |

- 句読点 `、。` の後には、`join_space` の値にかかわらず空白を入れない。
- 「全角文字」は表示幅が 2 の文字を指す(曖昧幅の文字は `ambiwidth` に従う)。
- 結合する行の行末の空白と、次の行のインデント・行頭記号は取り除いてから結合する。

### 3.5 段落とインデント

| キー | 型 | 既定値 | 意味 |
|---|---|---|---|
| `second_line_indent` | 真偽値 | `true` | 2 行目以降を元の 2 行目のインデントに合わせる(Vim の `fo=2` 相当)。また、前の行よりインデントが深くなった行で段落を分ける |
| `ideographic_space_paragraph` | 真偽値 | `true` | 全角スペース(U+3000)で始まる行を新しい段落とみなす |
| `expandtab` | 真偽値 | `false` | `true` なら継続行のインデントのタブを空白に展開する。`false` なら元のインデントをそのまま使う(空白をタブにまとめ直すことはしない) |
| `list_pattern` | 文字列 | `'^\s*(\d+[.)]\|[-*・])\s+'` | 箇条書きの判定パターン(正規表現)。一致した行で段落を分け、折り返した行は項目本文の位置に揃える。空文字列で無効 |
| `comments` | 文字列の配列 | `["n:>", "b:#", "://"]` | 行頭記号の一覧(下記)。折り返した行にも同じ記号を付ける |

段落の区切り:

- 空行(空白だけの行を含む)
- `ideographic_space_paragraph` が有効なとき、全角スペースで始まる行
- `list_pattern` に一致する行
- 行頭記号が前の行と異なる行
- `second_line_indent` が有効なとき、前の行よりインデントが深い行
  (インデントの深さは箇条書きの記号を含めて比べる。`1. item` の次の行が 3 桁の字下げなら同じ段落)

`comments` の書式は Vim の `'comments'` オプションの単純な形(`フラグ:文字列`)に合わせる。

| フラグ | 意味 |
|---|---|
| (なし) | 行頭記号 |
| `b` | 記号の後に空白が必要(`#include` などを除外する) |
| `n` | 入れ子にできる(`> > ` のような多重引用) |
| `f` | 1 行目だけに付く記号(折り返した行には付けず、その幅だけ字下げする) |

3 部構成のコメント(`/* * */`、Vim の `s` `m` `e` フラグ)は扱わない。

### 3.6 入出力

| キー | 型 | 既定値 | 意味 |
|---|---|---|---|
| `encoding` | 文字列 | `"auto"` | 入力の文字コード。`"auto"`(自動判定)、`"utf-8"`、`"utf-16le"`、`"utf-16be"`、`"cp932"`、`"euc-jp"`、`"iso-2022-jp"` のいずれか。出力も同じ文字コードになる(→ 1 章「文字コード」) |

## 4. 禁則処理の手順

用語:

- **ぶら下げ**: 行頭禁則文字が次の行の先頭に来そうなとき、`width` を超えても今の行末に残す。最大 `hang` 文字まで。
- **ぶら下げきれない場合**: 直前の文字を道連れにして次の行へ送り、行頭禁則を守る。
- **追い出し**: 行末禁則文字が行末に来そうなとき、次の行の先頭へ送る。

処理順:

1. UAX #14(および `ascii_break`、`strict`)で改行可能位置を求める
2. `no_line_start` の文字の前と、`no_line_end` の文字の後での改行を禁止する
   (UAX #14 が禁止している位置を許可することはしない。長音・小書き仮名の前の改行は `strict` で切り替える)
3. ぶら下げ・追い出しを適用して改行位置を決める

補足:

- ぶら下げた文字の後ろに空白が続く場合は、空白の後で改行できればぶら下げる
  (英文の `word,` の `,` も同様にぶら下げる)。
- `no_single_letter_end` が有効なとき、1 文字の単語の直後の改行位置は、他の改行位置がない場合にだけ使う。

### 幅を超える長い語

URL や長い英単語など、改行可能位置を含まず `width` より長い語は、分割しない。

- 行の途中に現れた場合は、その語の直前で改行して次の行へ送り、その行だけ `width` を超えて表示する。
- 語の後ろに続く文字は、次の改行可能位置から通常どおり折り返す。
- 語の直後に続く行頭禁則文字(例: `https://example.com/…。」` の `。」`)は、すべてその行に残す。
  この行は既に `width` を超えているので、`hang` の文字数制限は適用しない(道連れで語を分割しないため)。

例(`width = 20`):

```
詳細は https://example.com/very/long/path を参照。
```
↓
```
詳細は
https://example.com/very/long/path
を参照。
```

## 5. 実装方針

| 項目 | 方針 |
|---|---|
| ビルド設定 | `opt-level = "z"`、`lto = true`、`codegen-units = 1`、`panic = "abort"`、`strip = true` |
| C ランタイム | `+crt-static` で静的リンクし、DLL 不要の単体 exe にする |
| UAX #14 | `unicode-linebreak` クレート |
| 文字幅 | `unicode-width` クレート(`ambiwidth` に応じて CJK 幅を切り替え) |
| 文字コード変換・コンソール出力 | `windows-sys` クレート経由で Windows API(`MultiByteToWideChar`、`WideCharToMultiByte`、`GetConsoleMode`、`WriteConsoleW`)を呼ぶ |
| 正規表現 | `regex-lite` クレート(`regex` より約 400 KB 小さい) |
| 引数解析 | 自作(`clap` などのクレートは使わない) |
| 設定ファイル | TOML のサブセットを読む自作パーサ |
